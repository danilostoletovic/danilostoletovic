# Agent artifacts and maintenance

Astro prerenders the portfolio, public endpoints, and reports into `dist/`. The build hook writes deployment headers and discovery files from the same catalogue and capability definitions used by the pages and Worker. The build validates the output offline. Use Node.js 24 and the repository lockfile.

## Editing

1. Edit the typed professional content in `src/data/public.ts`. Edit scope examples in `src/data/budget.ts`. Change allowed crawler usage in `src/config/discovery.ts` and analytics endpoints or policy in `src/config/security.ts`.
2. For another public collection, add the public data and its strict output schema, then define the resource, associated tool, and representative queries in `src/lib/mcp-surface.ts`. The registry generates its JSON path, API catalog and OpenAPI entry, ARD discovery entry, A2A skill and Agent Skills package. Register its MCP callback in `workers/mcp.ts` and extend the SDK contract test. Keep public inputs separate from private configuration.
3. For an MCP tool, define the input with Zod and describe its behavior in `mcpTools`. Connect the implementation in the Worker. For the browser, opt the capability into `src/config/webmcp.ts` and exercise it in `verify-webmcp.mjs`. The lightweight browser validator handles integer constraints and string enums for the supported tools. Extend that validator and its tests if another field type is needed. Forms share their build-time metadata and let Chrome derive a schema from named controls.
4. Each resource registered in `resources` receives a generated `SKILL.md` and a digest. Update the resource entry or the shared generator when usage instructions change. Keep examples on public catalogue topics.
5. Run `npm run generate:artifacts` to rebuild and validate. Run `npm run verify:determinism` after a build to compare the complete output with a clean rebuild. The release marker depends on the selected commit environment variable.
6. Check upstream specifications separately with `npm run check:specs`. Add `-- --links` to also run the existing external link audit. Review each protocol change before updating its version constant, fixture or offline schema. Schema provenance is recorded in `scripts/schemas/README.md`. Normal builds validate locally using the pinned versions.
7. Start `npm run preview:worker` and run `npm test`, `npm run verify:browser` and `npm run verify:webmcp`. Follow the [Cloudflare deployment runbook](deployment.md) to release and check the edge response.
